# OrcaLoca django__django-11999 Disambiguation Stability Study

[中文 README](README_zh.md)

This repository contains a focused OrcaLoca localization study for
`django__django-11999`. It was created to answer two narrow reproduction
questions:

1. Does OrcaLoca's disambiguation decomposition stably improve this specific
   issue, or was an earlier `standard = match / no_disamb = miss` result an LLM
   path fluctuation?
2. Is OrcaLoca's inverted index an offline artifact or a runtime structure, and
   what does it contain for this issue?

Short answer: for this issue, the repeated test does **not** support a stable
disambiguation-only improvement claim. The no-disambiguation setting matched in
all 5 repeated runs, while the standard setting matched in 4 of 5 runs. A
stricter hidden-candidate ablation matched in 3 of 5 runs, but it only triggered
one hidden ambiguity message in these five runs, so it is best read as a
mechanism stress test rather than a stable accuracy estimate. The mechanism is
still real: disambiguation can convert ambiguous names such as `Field` into
executable high-priority search actions, but this issue is often solved by the
LLM directly proposing the exact path
`django/db/models/fields/__init__.py:Field.contribute_to_class`.

## Experiment

- Instance: `django__django-11999`
- Dataset wrapper: `SWE-bench_common`, split `test`
- Model: `gpt-5.4-mini`
- Backend: OpenAI-compatible endpoint configured through environment variables
- Trials: 5 standard runs, 5 no-disambiguation runs, and 5 stricter
  hidden-candidate runs
- Controlled variable:
  - `configs/search_standard.cfg`: class/file/disambiguation decomposition enabled
  - `configs/search_no_disamb.cfg`: only `disambiguation = False`
  - `configs/search_hidden_candidate_info.cfg`: `disambiguation = False`, and
    ambiguous search results are shown to the LLM only as
    `<AmbiguousSearch>` without candidate paths. Hidden candidates are recorded
    separately for analysis.
- Constant settings:
  - priority scheduling enabled
  - class decomposition enabled
  - file decomposition enabled
  - `top_k_disambiguation = 3`
  - `top_k_methods = 3`
  - `top_k_functions = 2`
  - `ORCALOCA_MAX_TOKENS = 4096`

API keys and endpoint values are not committed. The scripts only record whether
a key/base URL was present and which environment variable supplied the base URL.

Gold localization used for scoring:

```text
django/db/models/fields/__init__.py:Field.contribute_to_class
```

Interpretation:

- The old single-run Common93 difference is reproducible as a possible path, but
  not as a stable effect on this issue.
- `standard trial_02` is the clean mechanistic example: `search_class("Field")`
  returned 3 possible `Field` classes, and disambiguation decomposition converted
  them into concrete `search_class(..., file_path=...)` actions.
- `standard trial_05` missed because the LLM never searched `Field` or
  `contribute_to_class`; it stayed around `django/db/models/base.py`. A
  disambiguation module cannot help if no ambiguous query that names the correct
  entity is issued.
- `no_disamb trial_03` and `trial_05` still saw `<Disambiguation>` text, but no
  follow-up actions were generated by the disambiguation module. The LLM still
  recovered the correct function through direct exact-path actions.
- `hidden_candidate_info` replaces visible `<Disambiguation>` candidate lists
  with a short `<AmbiguousSearch>` notice and records the hidden candidates in a
  separate JSONL file. In this repeated run, only `trial_01` saw such a hidden
  ambiguity notice, for `Options`, not for the gold `Field.contribute_to_class`
  location. The two hidden-candidate misses stayed around
  `django/db/models/base.py` and never reached the correct field file.

## Run

```bash
export OPENAI_API_KEY=...
export OPENAI_BASE_URL=...

TRIALS=5 \
./scripts/run_django11999_stability_experiment.sh
```

The default runner executes `standard no_disamb`. To run only the stricter
hidden-candidate ablation:

```bash
RUN_GROUPS=hidden_candidate_info TRIALS=5 \
./scripts/run_django11999_stability_experiment.sh
```

If your OrcaLoca environment is not the active shell environment, pass
`PYTHON_BIN=/path/to/python`.

The runner writes temporary worktrees and caches under `work/`, then copies
compact logs and outputs into `artifacts/django11999/`.

## Runtime Inverted Index

OrcaLoca does not load a prebuilt offline inverted-index file. The index is
created at runtime:

1. `SearchManager.__init__()` calls `_setup_graph()`.
2. `_setup_graph()` constructs `RepoGraph(repo_path=...)`.
3. `RepoGraph.__init__()` creates `InvertedIndex()`.
4. `RepoGraph.build_whole_graph()` parses the checked-out repository and adds
   file, class, function and method names into the index.
5. `remove_single_value_key()` removes non-ambiguous keys, leaving only keys
   with multiple possible locations.

This study exports that runtime duplicate-key index for the Django checkout in:

- `artifacts/django11999/inverted_index/django_duplicate_inverted_index.jsonl`
- `artifacts/django11999/inverted_index/django_duplicate_index_stats.json`
- `artifacts/django11999/inverted_index/django11999_focused_queries.json`
- `artifacts/django11999/inverted_index/django11999_disambiguation_events.jsonl`
- `artifacts/django11999/inverted_index/django11999_selected_disambiguation_actions.txt`

## Key Questions

### Experiment Setting, LLM and Artifacts

This experiment runs 5 standard trials, 5 no-disambiguation trials, and 5
hidden-candidate trials for `django__django-11999`. The main controlled variable
is whether ambiguous candidate lists are automatically expanded, merely shown,
or hidden from the LLM. The localization model is `gpt-5.4-mini` through an
OpenAI-compatible API.

Intermediate artifacts are preserved under `artifacts/django11999/`, including
the final OrcaLoca localization JSON, main logs, action history logs,
disambiguation events, exported runtime inverted index and summary tables.

### Inverted Index

OrcaLoca's inverted index is not an offline file. It is built at runtime from
the checked-out target repository for each issue. This repository exports the
duplicate-key index built for the Django checkout used by `django__django-11999`
under `artifacts/django11999/inverted_index/`.

The exported index shows that `Field` has 3 candidate classes and
`contribute_to_class` has 14 candidate methods.

### Disambiguation Stability

This single-issue repeated experiment does not prove a stable disambiguation
benefit for `django__django-11999`: the standard setting matched in 4/5 runs,
while the no-disambiguation setting matched in 5/5 runs.

The logs still show the mechanism clearly. When the model searches an ambiguous
entity, OrcaLoca can expand the ambiguous name into concrete file-specific
search actions. This makes the issue useful as a mechanism case study, but not
as a stable single-issue improvement claim.

### Embedding Usage

This OrcaLoca localization path does not run OpenAI text embedding retrieval.
OrcaLoca does load local `bert-base-uncased` embeddings for observation
similarity checks used by early stop. The vendored Agentless code contains an
optional OpenAI `text-embedding-3-small` retrieval path for Agentless file
localization, but that path is not used in this OrcaLoca localization study.
